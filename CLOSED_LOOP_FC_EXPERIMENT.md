# Closed-loop evaluation of the existing fixed-continuation selector (`mu_FC`)

This experiment implements the minimal methodological step agreed for the
research proposal.

## What is trained

The selector is trained from the **existing state-level rollout dataset**.  In
that dataset, each candidate heuristic was evaluated as a fixed continuation
for the remaining horizon.  The resulting model is denoted `mu_FC`.

No Always-NT bootstrap is used.  Always NT is only an evaluation baseline.
No new counterfactual rollout labels are generated by this experiment.

## What changes at deployment

`mu_FC` is invoked repeatedly in a complete scenario:

1. observe the current state;
2. predict the fixed-continuation regret of every heuristic;
3. select the heuristic with the lowest predicted regret;
4. let that heuristic select the target to pursue;
5. keep pursuing that target until it is intercepted or crosses the boundary;
6. recompute the state and invoke `mu_FC` again.

New target arrivals, interceptions of other nearby targets, and penetrations of
other targets update the next state but do not pre-empt the currently selected
target.

This produces a true closed-loop sequence such as:

```text
NT -> FMTTB -> FNI -> NT -> FCluster -> ...
```

although the supervised labels used to train `mu_FC` are still the original
fixed-continuation labels.  Adaptive relabeling/policy iteration is deliberately
left as a later doctoral extension.

## Main command

```bash
python -m src.experiments.run_closed_loop_fc_selector_experiment \
  --rollout-input-dir /path/to/existing/large_scale_output \
  --output-dir outputs/closed_loop_mu_fc \
  --dataset-mode no_ties \
  --scenario-mix decision_rich \
  --n-test-scenarios 250 \
  --test-seed 20260810
```

For a quick smoke test:

```bash
python -m src.experiments.run_closed_loop_fc_selector_experiment \
  --rollout-input-dir /path/to/existing/large_scale_output \
  --output-dir outputs/closed_loop_mu_fc_smoke \
  --dataset-mode no_ties \
  --n-estimators 50 \
  --n-test-scenarios 20 \
  --bootstrap-samples 200
```

The final selector is saved as:

```text
mu_fc_selector.joblib
```

It can be reused without retraining:

```bash
python -m src.experiments.run_closed_loop_fc_selector_experiment \
  --model-in outputs/closed_loop_mu_fc/mu_fc_selector.joblib \
  --output-dir outputs/closed_loop_mu_fc_repeat \
  --n-test-scenarios 250 \
  --test-seed 20260811
```

## Important outputs

- `mu_fc_internal_validation_summary.csv` — replication-style internal
  validation on the existing state-level dataset.
- `closed_loop_policy_results_by_scenario.csv` — complete-scenario outcomes for
  `mu_FC` and every fixed heuristic on exactly the same test scenarios.
- `closed_loop_policy_summary.csv` — mean complete-scenario performance.
- `closed_loop_paired_comparison_vs_always_nt.csv` — paired difference, win/tie/
  loss rates, and bootstrap confidence interval versus Always NT.
- `adaptive_mu_fc_decision_log.csv` — heuristic and target selected at every
  decision epoch.
- `adaptive_mu_fc_heuristic_usage.csv` — how often each heuristic was selected.
- `adaptive_vs_best_fixed_hindsight.csv` — comparison with the best fixed
  heuristic observed in hindsight for each scenario.  This is **not** a global
  adaptive oracle.

## Oracle terminology

This experiment does not compute the global adaptive oracle.  That would require
searching a combinatorial tree of heuristic sequences.  The current comparisons
are:

- each fixed heuristic;
- Always NT, the strongest fixed baseline in the preliminary experiment;
- the best fixed heuristic in hindsight for each scenario;
- the closed-loop `mu_FC` selector.

Exact or depth-limited adaptive oracle calculations can be added later on a
small benchmark suite without blocking the present proposal experiment.
